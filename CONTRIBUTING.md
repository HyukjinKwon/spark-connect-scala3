# Contributing

Thanks for your interest in improving **spark-connect-scala3**. Contributions of
all kinds - bug reports, documentation, examples, and code - are welcome.

## Development setup

Prerequisites:

- JDK 17 or newer (Temurin recommended)
- [sbt](https://www.scala-sbt.org/) 1.10+
- Java 17+ is also what you need to run a local Spark Connect server for the
  integration tests

```bash
git clone https://github.com/HyukjinKwon/spark-connect-scala3
cd spark-connect-scala3
sbt compile
```

The build has three modules:

- `proto` - the ScalaPB-generated gRPC and message classes, compiled from the
  vendored Spark Connect protobuf definitions under
  `modules/proto/src/main/protobuf/`.
- `client` - the public client API under `org.apache.spark.sql.*`.
- `examples` - runnable example programs (not published).

## Building and testing

```bash
sbt clean compile          # compile every module
sbt test                   # run the unit tests (no server required)
sbt scalafmtCheckAll       # verify formatting
sbt scalafmtAll            # apply formatting
```

Unit tests must not require a live server: they assert on the protobuf plan a
DataFrame builds, or decode fixed Arrow payloads.

### Integration tests

Integration tests run against a live Spark Connect server and are selected by a
`*Integration*` test-name glob. Start a server first, then point the tests at it
with `SPARK_CONNECT_TEST_REMOTE`:

```bash
# Download and start a server (Spark 4.0+ bundles the Connect server).
curl -L https://archive.apache.org/dist/spark/spark-4.1.2/spark-4.1.2-bin-hadoop3.tgz -o spark.tgz
tar xzf spark.tgz
./spark-4.1.2-bin-hadoop3/sbin/start-connect-server.sh

# Run the integration tests against it.
SPARK_CONNECT_TEST_REMOTE=sc://localhost:15002 sbt "client/testOnly *Integration*"
```

## Running the examples

```bash
sbt "examples/runMain examples.QuickStart"
sbt "examples/runMain examples.Aggregations"
sbt "examples/runMain examples.JoinExample"
```

Each example connects to `$SPARK_REMOTE` (default `sc://localhost:15002`) or to
the connection string passed as the first program argument.

## Code style

Formatting is enforced with [scalafmt](https://scalameta.org/scalafmt/); the
`.scalafmt.conf` at the repository root is the source of truth. Run
`sbt scalafmtAll` before pushing, and keep `sbt scalafmtCheckAll` green.

Conventions:

- Mirror the Apache Spark Scala DataFrame API names and semantics. Note any
  intentional deviation in a comment.
- Keep the `proto` module a thin, generated layer; put behavior in `client`.
- Document public types and methods with Scaladoc.

## Regenerating the protobuf stubs

The stubs are generated by the `proto` module at build time from the vendored
`.proto` files. Bump them only when moving to a new Spark Connect protocol
version, by updating the files under
`modules/proto/src/main/protobuf/spark/connect/` and recompiling.

## Pull requests

1. Fork and create a feature branch.
2. Add or update tests for your change; keep the suite green.
3. Run `sbt scalafmtCheckAll test` before pushing.
4. Open a PR with a clear description of the motivation and behavior.
